# CompTIA Security+ (SY0-701) Study Notes

## Domain 2.0: Threats, Vulnerabilities, and Mitigations (22%)

### Objective 2.2: Threat Vectors and Attack Surfaces

---

## 1. Core Distinction

* **Threat Vector:** The **path, method, or conduit** an attacker uses to deliver a payload, initiate an exploit, or gain unauthorized access (the *"how"* or delivery mechanism).
* **Attack Surface:** The **sum total of all accessible points, vulnerabilities, and interfaces** across an organization that an adversary could attempt to exploit (the *"where"* or exposure zone).
* **Primary Defense Goal:** Minimize the attack surface through hardening, least functionality, segmentation, and strict authorization.

---

## 2. Threat Vectors

### 2.1 Messaging & Social Vectors
* **Email (Phishing):**
  * **Phishing:** Broad, untargeted fraudulent messages mimicking trustworthy entities to harvest credentials or deliver malicious attachments.
  * **Spear Phishing:** Highly customized, targeted phishing directed at specific individuals or roles using gathered reconnaissance data.
  * **Whaling:** Spear phishing targeting high-level executives (C-level, board members, directors) or prominent public officials.
* **SMS (Smishing):**
  * Delivery of fraudulent links or instructions via SMS text messaging.
  * Leverages higher mobile trust levels and urgency (fake delivery tracking, bank fraud alerts, MFA resets).
* **Voice Calls (Vishing):**
  * Phishing carried out over traditional telephone or VoIP networks.
  * Attackers spoof caller ID to impersonate tech support, banks, or law enforcement.
  * **AI Voice Cloning:** Generative audio models synthesizing executives' or colleagues' voices to authorize emergency fund transfers or bypass verbal authentication.

### 2.2 Technical, Third-Party & Physical Vectors
* **Supply Chain Compromise:**
  * Infiltrating an organization indirectly by compromising upstream third-party vendors, suppliers, or software dependencies trusted by the target.
  * **Software Supply Chain:** Tampering with source code repositories, open-source packages (`npm`, `pip`), or vendor update servers (e.g., SolarWinds Orion) so clients automatically download backdoored, signed updates.
  * **Hardware Supply Chain:** Modifying chips, boards, or firmware in transit or during manufacturing.
* **Removable Media:**
  * Portable physical storage (USB flash drives, external drives, SD cards) used as delivery conduits.
  * **USB Drop Attack:** Leaving weaponized drives in parking lots or lobbies labeled with enticing titles to exploit human curiosity.
  * **BadUSB / HID Spoofing:** USB hardware programmed to masquerade as a Human Interface Device (keyboard) to bypass storage blocklists and auto-inject malicious keystrokes/commands.
  * **Mitigations:** Endpoint Group Policy disabling USB storage, endpoint encryption, physical USB port locks.
* **Unsecure Wireless Networks:**
  * Untrusted, open, or misconfigured Wi-Fi networks allowing signal interception.
  * **Evil Twin / Rogue Access Point:** Unauthorized hotspot broadcasting an identical SSID to trick victim devices into auto-connecting.
  * **Passive Eavesdropping:** Sniffing cleartext traffic over unencrypted radio frames using monitor mode and packet analyzers.
  * **On-Path (MitM) Attacks:** Intercepting and altering data packets passing between the client and default gateway (e.g., via ARP poisoning or malicious AP routing).
  * **Mitigations:** Mandatory corporate VPN tunnels, WPA3-Enterprise, 802.1X network access control, Wireless Intrusion Prevention Systems (WIPS).

## 3. Attack Surfaces

### 3.1 Perimeter Attack Surface
* **Definition:** The boundary between the untrusted public internet and the internal trusted private corporate network.
* **Components:** External firewalls, edge routers, VPN concentrators, public IP spaces, exposed ports (e.g., SSH, RDP, HTTPS).
* **Key Architecture & Devices:**
  * **VPN Concentrator:** High-capacity hardware/virtual appliances dedicated to encrypting, decrypting, and terminating concurrent IPsec/SSL remote access tunnels.
  * **DMZ / Screened Subnet:** A segmented buffer zone between external and internal firewalls hosting public-facing servers (web, DNS, mail). Protects the internal private LAN even if the public server is compromised.
* **Hardening:** Close unused ports, disable legacy protocols, restrict edge management interfaces, enforce strict firewall ingress ACLs.

### 3.2 Applications Attack Surface
* **Definition:** All custom, enterprise, and third-party software code executed by the organization.
* **Common Vulnerabilities (OWASP Top 10):**
  * **SQL Injection (SQLi):** Malicious database queries executed via unsanitized user inputs.
  * **Cross-Site Scripting (XSS):** Malicious client-side scripts running inside victim browsers.
  * **Buffer Overflow:** Overwriting system memory boundaries leading to denial of service or arbitrary code execution.
* **Hardening:** Static/Dynamic Application Security Testing (SAST/DAST), parameterized queries/input sanitization, Web Application Firewalls (WAF).

### 3.3 APIs (Application Programming Interfaces) Attack Surface
* **Definition:** Programmatic interfaces (REST, GraphQL) enabling backend services, mobile apps, and microservices to exchange structured data (JSON/XML).
* **Common Vulnerabilities:**
  * **BOLA / IDOR (Broken Object Level Authorization):** Modifying identifier values (e.g., `/api/user/101` to `/api/user/102`) to view unauthorized records due to missing ownership checks.
  * **Lack of Rate Limiting:** Exposing endpoints to high-frequency scraping, credential stuffing, or resource exhaustion.
  * **Shadow / Zombie APIs:** Unmonitored, legacy, or test APIs running without authentication.
* **Hardening Controls:**
  * **API Gateways:** Central reverse-proxies handling token validation, routing, traffic shaping, and unified auditing.
  * **Object-Level Validation:** Verifying user authorization against the exact requested resource record on every single database call.
  * **Rate Limiting:** Enforcing maximum requests per time window per IP/token (returns HTTP 429 Too Many Requests).

### 3.4 Cloud Environments Attack Surface
* **Shared Responsibility Model:**
  * **Cloud Provider:** Security **of** the cloud (data centers, physical servers, host hypervisors, foundational network).
  * **Customer:** Security **in** the cloud (customer data, operating system configurations, IAM access controls, firewall/Security Group rules).
* **Primary Risks:**
  * **Public Storage Buckets:** Misconfigured cloud object storage (AWS S3, Azure Blob) exposed without authentication.
  * **Permissive IAM Policies:** Over-privileged roles, excessive wildcard (`*`) access, lack of MFA on administrative consoles.
  * **Exposed API / Access Keys:** Credentials inadvertently committed to public code repositories.

### 3.5 Human / Social Engineering Attack Surface
* **Definition:** Exploitation of human behavior, trust, and psychological pressure rather than technical code flaws.
* **Core Psychological Principles Exploited:** Urgency, Authority, Fear, Consensus/Social Proof, Scarcity, Familiarity.
* **Physical & Environmental Social Attacks:**
  * **Shoulder Surfing:** Observing screen displays or keypads to steal passwords, confidential records, or PINs.
    * *Mitigation:* **Privacy Filters** (polarized films using micro-louvers that block screen viewing angles outside a narrow 60° forward cone).
  * **Tailgating / Piggybacking:** Slipping through secure physical access doors directly behind an authorized person without scanning a separate credential.
    * *Mitigations:* **Mantraps / Access Control Vestibules** (two interlocking doors where both cannot be open simultaneously, verified via biometric, card, or weight sensors) and optical **Turnstiles**.
  * **Watering Hole Attacks:** Compromising a legitimate third-party website frequently visited by the targeted organization's staff to deliver drive-by malware.
* **Mitigations:** Continuous interactive security awareness training, phishing simulation drills, and mandatory verification procedures for sensitive/financial actions.

## 4. Key Acronyms Quick Reference

* **ACL:** Access Control List
* **API:** Application Programming Interface
* **BOLA:** Broken Object Level Authorization
* **DAST:** Dynamic Application Security Testing
* **DMZ:** Demilitarized Zone (Screened Subnet)
* **HID:** Human Interface Device
* **IAM:** Identity and Access Management
* **IDOR:** Insecure Direct Object Reference
* **SAST:** Static Application Security Testing
* **Vishing:** Voice Phishing
* **WAF:** Web Application Firewall
* **WIPS:** Wireless Intrusion Prevention System
