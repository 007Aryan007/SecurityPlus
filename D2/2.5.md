# CompTIA Security+ (SY0-701)

## Section 2.5 - Mitigation Techniques

### 1. Network Mitigation & Segmentation

* **VLANs (Virtual Local Area Networks):** Logically segmenting a network at the switch level. It allows multiple isolated networks (e.g., HR, IT, Guest) to run on the exact same physical hardware without seeing each other's traffic.

* **DMZ (Demilitarized Zone / Screened Subnet):** A heavily monitored buffer network designed for public-facing servers (like web servers or email gateways). 
  * *Architecture:* Public users can access the DMZ, but the DMZ cannot freely access the secure internal network where the databases live. If a web server is hacked, the attacker is trapped in the buffer zone.

* **ACLs (Access Control Lists):** The "security guards" for network segments. A top-down list of rules on a firewall or router dictating what traffic is permitted.
  * *Exam Trick:* Traffic is evaluated against rules from top to bottom. If it doesn't match an explicit `ALLOW` rule, it hits the **Implicit Deny** rule at the very bottom and is dropped.

### 2. Host & System Mitigation

* **System Hardening:** The process of reducing a system's "attack surface" (potential vulnerabilities). This includes changing default passwords, closing unused ports, and uninstalling unnecessary bloatware or services.

* **Baseline Configuration Enforcement:** Taking a snapshot of a perfectly hardened system (the baseline) and using automated tools (like Active Directory Group Policy) to constantly monitor systems. If a machine drifts from the baseline, it is forced back into the secure state.

* **Automated Patch Deployment:** Using centralized servers to push OS and software updates.
  * *Exam Rule:* **Never** automate patches directly to production all at once. You must always test patches in an isolated staging environment first, then deploy them to production in phased groups to prevent network-wide crashes.

* **Air-Gapping & Isolation:** The ultimate network security. A system that is physically and logically disconnected from all other networks (including the internet).
  * *Use Cases:* Industrial Control Systems (ICS/SCADA), highly classified systems, and **Root CAs**.
  * *Vulnerability:* Can only be compromised via physical access (e.g., plugging in a malicious USB drive / "Sneakernet").

### 3. Deep Dive: PKI & Certificates (The Exam Favorites)

* **The Root CA (Certificate Authority):** The master key of the enterprise. It is kept **air-gapped (offline)** in a physical vault to prevent massive compromise. It only issues certificates to Intermediate CAs.

* **Intermediate CAs:** The servers that stay *online* to issue certificates to everyday devices, servers, and users.

* **Digital Certificates vs. Keys:**
  * **Digital Certificate:** A digital ID card. It contains the server's identity, the CA's signature, and the **Public Key** (which is shared with the world).
  * **Private Key:** A highly guarded secret file that stays on the server. It is *never* put inside the certificate and *never* shared. Data encrypted by the Public Key can only be decrypted by the Private Key.

* **What relies on Certificates?**
  * **HTTPS/TLS:** Web traffic encryption.
  * **802.1X / VPNs:** Device and user authentication.
  * **Code Signing:** Used by **UEFI Secure Boot** to verify operating system files haven't been tampered with.
  * **Smart Cards:** Physical IDs containing certificates for enterprise login.
