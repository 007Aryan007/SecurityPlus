# CompTIA Security+ Notes: 3.3 Data Protection

This section covers the core concepts of data security, including how data is classified, the states it exists in, and the specific technologies used to protect it from unauthorized access and exfiltration.

## 1. Data States

To properly secure data, you must apply the correct controls based on what the data is currently doing.

* **Data at Rest:** Data that is currently in storage (hard drives, databases, flash drives, backups).
  * **Protection:** Encrypt the storage medium. Common methods include Full Disk Encryption (FDE), Self-Encrypting Drives (SEDs), and strong symmetric algorithms like AES.
* **Data in Transit (Data in Motion):** Data actively moving across a network (e.g., downloading a file, sending an email, web traffic).
  * **Protection:** Encrypt the transmission tunnel. Common methods include TLS/HTTPS for web traffic and IPsec for VPNs.
* **Data in Use:** Data actively processing in memory (RAM) or the CPU. This is the most vulnerable state because data must typically be decrypted to be processed.
  * **Protection:** Extremely difficult to protect. Modern solutions include "secure enclaves" (hardware-level isolation), confidential computing, and homomorphic encryption (allowing computation on ciphertext).

## 2. Data Classifications

Proper classification ensures that the appropriate level of security funding and controls are applied to the most critical information.

### Regulatory / Compliance Types
* **PII (Personally Identifiable Information):** Any data that can identify a specific individual. Examples: Full name, Social Security Number (SSN), biometric data, driver's license number.
* **PHI (Protected Health Information):** Health/medical data tied to an individual, heavily regulated in the US by HIPAA. Examples: Medical records, health insurance information.
* **PCI-DSS (Payment Card Industry Data Security Standard):** While technically a standard rather than a data type, the exam uses this to refer to **Cardholder Data (CHD)**. Examples: Credit card numbers, expiration dates, CVV codes.

### Sensitivity Levels (Organizational)
Organizations typically rank data from least to most sensitive:
* **Public:** Information approved for public release. Disclosure causes no harm (e.g., marketing materials, press releases).
* **Internal (Private):** Data for employees only. Unauthorized disclosure could cause minor embarrassment or competitive disadvantage (e.g., company memos, internal directories).
* **Confidential:** Sensitive business information. Disclosure causes significant damage (e.g., trade secrets, source code, financial forecasts).
* **Restricted:** Highly sensitive data with strict need-to-know access. Disclosure causes severe, potentially catastrophic damage (e.g., top-secret government clearance data, major unannounced M&A plans).

## 3. Securing Methods

These are the technical controls and processes used to enforce data protection policies.

### Data Loss Prevention (DLP)
* **Definition:** Software or hardware solutions designed to detect and prevent unauthorized data exfiltration (data leaving the organization).
* **Function:** DLP inspects data for sensitive patterns (like the 9-digit format of an SSN or 16 digits of a credit card) and blocks the action (e.g., preventing a user from attaching a sensitive file to a personal Gmail account or copying it to a USB drive).
* **Locations:** Can be deployed at the Network level (monitoring internet traffic), Endpoint level (installed on user laptops), or Cloud level.

### Encryption, Tokenization & Masking
* **Encryption:** Cryptographically transforming plaintext data into unreadable ciphertext using an algorithm and a key. It is reversible if you have the key.
* **Tokenization:** Replacing sensitive data with a randomly generated, non-sensitive placeholder (a "token"). The real data is stored securely in a central vault. If the token is stolen, it is completely useless to the attacker. Heavily used in PCI-DSS (payment processing).
* **Masking:** Obscuring portions of the data to protect it while keeping its format usable. For example, replacing a credit card number with `****-****-****-1234`. Often used when providing production databases to developers for testing.

### Sanitization and Destruction
When hardware reaches the end of its life, data must be securely removed to prevent recovery.
* **NIST 800-88:** The gold-standard government guideline for media sanitization. It defines three levels: Clear (logical software wipe), Purge (degaussing or firmware commands), and Destroy (physical destruction like shredding or incinerating).
* **Crypto-shredding (Cryptographic Erase):** An incredibly fast and effective way to sanitize a disk. You encrypt the entire drive with a strong key, and when it's time to dispose of the drive, you securely destroy the decryption key. Without the key, the data is permanently irretrievable, even if the physical disk remains intact.
