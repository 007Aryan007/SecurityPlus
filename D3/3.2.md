# CompTIA Security+ Notes: 3.2 Enterprise Infrastructure Principles

This section focuses on how to design secure enterprise networks using layered defenses, specialized infrastructure components, and secure communication protocols. 

## 1. Infrastructure Considerations & Principles

A secure network architecture assumes that attacks will happen and builds multiple barriers to stop or slow down an attacker.

### Defense-in-Depth
* **Definition:** A strategy that employs multiple layers of overlapping security controls (firewalls, IDS/IPS, endpoint protection, physical security, policies). 
* **Concept:** If an attacker breaches one layer (e.g., bypasses the firewall), another layer (e.g., Host-based IPS) should block them. Also known as "layered security."
* **Key aspects:** Includes **vendor diversity** (using products from different manufacturers so a single zero-day exploit doesn't compromise the whole network) and **control diversity** (mixing technical, administrative, and physical controls).

### Jump Boxes / Bastion Hosts
* **Definition:** A heavily secured, hardened server situated in a controlled network zone (often a DMZ or dedicated management VLAN) used specifically by administrators to connect to internal secure networks.
* **Security Function:** Instead of allowing direct remote access (like SSH or RDP) from the internet to internal servers, admins must first securely log into the jump box. The jump box is tightly monitored, logs all activity, and serves as the single point of entry, reducing the attack surface.

### Proxies
Proxies act as intermediaries between a client and a server. 

* **Forward Proxy:** 
  * **Location:** Sits between internal corporate users and the external internet.
  * **Purpose:** **Protects the clients.** It filters outbound traffic, blocks access to malicious or non-work-related websites (content/URL filtering), caches frequently accessed web pages to save bandwidth, and hides the internal IP addresses of the clients from the internet.
* **Reverse Proxy:** 
  * **Location:** Sits between the external internet and internal corporate web servers.
  * **Purpose:** **Protects the servers.** It accepts incoming web requests from the internet and forwards them to the internal servers. It provides load balancing, hides the true IP of the web servers, and often performs SSL/TLS offloading (handling the encryption/decryption process to reduce the load on the web servers).

## 2. Secure Communication Protocols

The Security+ exam frequently tests your knowledge of secure protocols versus their older, unencrypted (plaintext) counterparts. **Always choose the secure version.**

### TLS/HTTPS (Port 443)
* **Replaces:** HTTP (Port 80). SSL is deprecated; TLS is the modern standard.
* **Function:** Encrypts web traffic between a browser and a web server using certificates. Protects against eavesdropping and Man-in-the-Middle (MitM) attacks.

### SSH (Secure Shell) (Port 22)
* **Replaces:** Telnet (Port 23) - Telnet sends passwords in cleartext!
* **Function:** Provides a secure, encrypted command-line interface to remotely manage servers and network devices. Supports public key authentication.

### SFTP (Secure File Transfer Protocol) (Port 22)
* **Replaces:** FTP (Ports 20/21).
* **Function:** Transfers files securely. Because it runs over an SSH session, it uses Port 22 and encrypts both the authentication credentials and the data payload. *(Note: Do not confuse with FTPS, which is FTP over SSL/TLS on ports 989/990).*

### IPsec (Internet Protocol Security)
* **Replaces:** Standard, unencrypted IP traffic.
* **Function:** A suite of protocols used to authenticate and encrypt every IP packet of a communication session. Most commonly used to create secure **VPNs** (Virtual Private Networks).
* **Core Components:**
  * **AH (Authentication Header):** Provides integrity and data origin authentication (proves who sent it and that it wasn't changed).
  * **ESP (Encapsulating Security Payload):** Provides encryption (confidentiality) for the payload.
* **Modes:**
  * **Transport Mode:** Only the payload of the packet is encrypted (used for host-to-host).
  * **Tunnel Mode:** The entire IP packet is encrypted and placed inside a new IP packet (used for network-to-network/VPNs).

### DNSSEC (Domain Name System Security Extensions)
* **Replaces:** Standard DNS (Port 53), which is vulnerable to spoofing.
* **Function:** Secures DNS queries by adding cryptographic digital signatures to DNS records. It ensures the integrity and authenticity of DNS data, preventing attacks like **DNS poisoning** (where an attacker redirects traffic to a malicious site by forging DNS responses).

### SNMPv3 (Simple Network Management Protocol version 3) (Ports 161/162)
* **Replaces:** SNMPv1 and SNMPv2, which used cleartext "community strings" (essentially unencrypted passwords).
* **Function:** Used to monitor, configure, and manage network devices (routers, switches). SNMPv3 adds strong **authentication** and **encryption**, ensuring that attackers cannot intercept network metrics or maliciously alter device configurations.
