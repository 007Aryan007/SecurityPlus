# CompTIA Security+ Notes: 3.1 Architecture Models

This section covers various IT environments, specialized systems, and modern infrastructure deployment methods, with a focus on their security implications.

## 1. Environments

Understanding where and how data is processed is critical for applying the correct security controls and understanding the **Shared Responsibility Model**.

### On-Premises
*   **Definition:** All hardware, software, and networking are owned, managed, and located within the organization's physical facilities.
*   **Security Implications:** The organization has complete control but also 100% of the responsibility for security (physical, network, host, and application).

### Cloud Computing Service Models
*   **IaaS (Infrastructure as a Service):** Vendor provides the hardware (servers, storage, networking). *Example: AWS EC2.*
    *   **Security:** You manage the OS, applications, and data. Vendor secures the physical hardware and hypervisor.
*   **PaaS (Platform as a Service):** Vendor provides the hardware and the OS/environment. *Example: Heroku, AWS Elastic Beanstalk.*
    *   **Security:** You manage the applications and data. Vendor secures the OS, hardware, and runtime environment.
*   **SaaS (Software as a Service):** Vendor provides a fully functional application. *Example: Microsoft 365, Google Workspace.*
    *   **Security:** You only manage your data and user access (IAM). Vendor manages everything else.

### Cloud Deployment Models
*   **Public Cloud:** Services provided over the internet to the general public. Multi-tenant environment.
*   **Private Cloud:** Services dedicated to a single organization. Can be hosted on-prem or by a third party.
*   **Hybrid Cloud:** A mix of public and private clouds, bound together by technology that allows data and applications to be shared.
*   **Multi-Cloud:** Using multiple public cloud providers (e.g., using both AWS and Azure) to avoid vendor lock-in or leverage specific vendor strengths.

### Modern Computing Models
*   **Serverless Architecture:** Developers write code (functions) without provisioning or managing the underlying servers. The cloud provider automatically provisions resources as needed (e.g., AWS Lambda).
    *   **Security:** Reduces attack surface at the OS level, but requires strong application security and IAM controls.
*   **Edge Computing:** Processing data closer to the source (the "edge" of the network) rather than sending it all to a centralized cloud. 
    *   **Security:** Reduces latency and bandwidth, but increases the physical attack surface. Devices must be physically secured and use encrypted communications.

## 2. Embedded & Specialized Systems

These are purpose-built systems that often lack traditional security capabilities (like installing an antivirus).

### Internet of Things (IoT)
*   **Definition:** Smart, internet-connected devices (smart thermostats, IP cameras, medical devices).
*   **Security Challenges:** 
    *   Often have weak default credentials.
    *   Difficult or impossible to patch (firmware updates are rare).
    *   Limited compute resources (cannot run traditional security agents).
    *   **Mitigation:** Network segmentation (put IoT devices on their own VLAN), change default passwords, disable unnecessary services.

### Industrial Control Systems (ICS) / SCADA
*   **Definition:** Systems used to monitor and control industrial processes (manufacturing, power grids, water treatment). SCADA (Supervisory Control and Data Acquisition) is a type of ICS used for large-scale, geographically dispersed systems.
*   **Security Challenges:** 
    *   Historically designed for reliability, not security.
    *   Cannot be easily taken down for patching.
    *   **Mitigation:** Air-gapping (physical isolation from other networks), strict network segmentation, unidirectional gateways (data diodes).

## 3. Infrastructure as Code (IaC)

IaC is the process of managing and provisioning computer data centers through machine-readable definition files (code), rather than physical hardware configuration or interactive configuration tools.

### Automation Templates
*   **Definition:** Scripts or code files (e.g., Terraform, AWS CloudFormation, Ansible) used to rapidly and consistently deploy infrastructure.
*   **Security Benefit:** Reduces human error. Security controls can be built directly into the templates, ensuring every deployment is secure by default.

### Configuration Drift Management
*   **Definition:** Configuration drift happens when a system's actual configuration deviates from its baseline (desired) configuration over time, often due to manual, undocumented changes.
*   **Security Implication:** Drift can introduce vulnerabilities. IaC tools continuously monitor the environment and automatically correct (or alert on) unauthorized changes to bring the system back to its baseline.

### Immutable Infrastructure
*   **Definition:** Servers and infrastructure are never modified after they are deployed. 
*   **Security Implication:** If a server needs a patch or an update, you do not log into it and update it. Instead, you update the IaC template, deploy a brand new server with the patch applied, and destroy the old one. This eliminates configuration drift, prevents malicious persistence (malware is wiped out when the server is replaced), and ensures consistency.
