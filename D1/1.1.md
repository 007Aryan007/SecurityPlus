# CompTIA Security+ (SY0-701) Study Notes

## Domain 1.0: General Security Concepts (12%)

### Objective 1.1: Compare and contrast various types of security controls

---

## 1. Overview of Security Controls

A **security control** is any safeguard, countermeasure, or procedure designed to preserve the confidentiality, integrity, and availability (CIA triad) of an organization's systems, data, and infrastructure.

In CompTIA Security+ (SY0-701), controls are categorized along two fundamental dimensions:
1. **Control Category (How the control is implemented)**
2. **Control Functional Type (The goal/action the control performs)**

---

## 2. Control Categories (Implementation Methods)

Control categories describe the **mechanism or domain of implementation**.

```
                           ┌──────────────────────────────┐
                           │   Security Control Categories│
                           └──────────────┬───────────────┘
                                          │
         ┌──────────────────┬─────────────┴──────┬──────────────────┐
         │                  │                    │                  │
    [Technical]        [Managerial]        [Operational]       [Physical]
 (Hardware/Software)  (Policy/Governance) (Human/Daily Tasks) (Tangible/Real World)
```

### 2.1 Technical Controls (Logical Controls)
* **Definition:** Controls implemented and enforced through technology—specifically computer hardware, firmware, software, network protocols, or operating systems.
* **Core Characteristics:** Automated, programmatic, logical enforcement.
* **Examples:**
  * Firewalls, Next-Generation Firewalls (NGFW), and Web Application Firewalls (WAF).
  * Encryption mechanisms (IPsec, TLS, AES full-disk encryption).
  * Access Control Lists (ACLs) and network segmentation.
  * Antivirus / Endpoint Detection and Response (EDR) software.
  * Multi-Factor Authentication (MFA) prompts.
  * Intrusion Detection/Prevention Systems (IDS/IPS).

### 2.2 Managerial Controls (Administrative Controls)
* **Definition:** Controls focused on overarching governance, strategic risk management, legal requirements, and regulatory compliance set by organizational leadership.
* **Core Characteristics:** Executive decisions, organizational frameworks, formal oversight.
* **Examples:**
  * Information security policies (e.g., Acceptable Use Policy [AUP], Password Policy).
  * Risk assessments and Business Impact Analyses (BIA).
  * Vendor selection governance and third-party risk management frameworks.
  * Change management authorization standards.
  * Data classification and retention guidelines.

### 2.3 Operational Controls (Procedural Controls)
* **Definition:** Controls carried out by people through daily procedures, repetitive workflows, and routine operational habits to sustain the security posture.
* **Core Characteristics:** Human execution, operational adherence, process-driven.
* **Examples:**
  * User onboarding and offboarding execution.
  * Security awareness and anti-phishing simulation training.
  * Performing routine system backups and log monitoring reviews.
  * Scheduled physical facility walkthroughs and visitor logging.
  * Incident response tabletop exercises.

### 2.4 Physical Controls
* **Definition:** Tangible, real-world safeguards designed to prevent unauthorized physical contact, access, or environmental damage to facilities, hardware, and staff.
* **Core Characteristics:** Material/physical objects you can touch; barriers in the physical domain.
* **Examples:**
  * Perimeter security: Fences, gates, lighting, vehicle bollards.
  * Entry control: Biometric door locks, card readers, mantraps / access control vestibules, turnstiles.
  * Surveillance: Closed-Circuit Television (CCTV) cameras.
  * Environmental controls: Fire suppression systems (clean agent/sprinklers), HVAC cooling units, uninterruptible power supplies (UPS).
  * Cable locks and physical USB port blockers.

## 3. Control Functional Types (Actions & Objectives)

Control functional types define **when and how** a control acts relative to a security event or incident.

### 3.1 Preventive Controls
* **Objective:** **Stop** a security incident or unauthorized action from occurring in the first place.
* **Timing:** Proactive (Pre-incident).
* **Examples:**
  * Firewall blocking ingress traffic on an unapproved port.
  * Account lockouts stopping continuous brute-force password guessing.
  * Mantrap preventing an unauthorized person from entering a data hall.
  * Requiring MFA prior to granting access to a cloud dashboard.

### 3.2 Deterrent Controls
* **Objective:** **Discourage** a potential adversary from attempting an attack or policy violation by signaling negative consequences or increased difficulty.
* **Timing:** Psychological discouragement prior to an attack.
* **Key Distinction:** A deterrent does not physically stop the attacker; it seeks to convince them not to try.
* **Examples:**
  * Warning banners on login screens ("Unauthorized access is monitored and prosecuted").
  * Visible CCTV cameras and prominent warning signs ("Premises Under Video Surveillance").
  * Uniformed armed security guards stationed at building entrances.
  * Lighting around the perimeter fence line.

### 3.3 Detective Controls
* **Objective:** **Identify and record** an ongoing or completed security incident, policy violation, or unauthorized activity.
* **Timing:** During or immediately after an incident occurs.
* **Examples:**
  * Intrusion Detection Systems (NIDS/HIDS) generating alerts on signature matches.
  * Log aggregation systems (SIEM) recording failed login events.
  * Security guards reviewing live CCTV camera feeds.
  * Motion sensors and infrared break-beam alarms inside server rooms.
  * Audit logs and File Integrity Monitoring (FIM).

### 3.4 Corrective Controls
* **Objective:** **Reverse the damage**, remediate the impact, or restore systems back to an operational state after an incident has occurred.
* **Timing:** Post-incident.
* **Examples:**
  * Restoring encrypted database files from verified offline backups following a ransomware outbreak.
  * Quarantining or deleting infected binaries via endpoint antivirus.
  * Applying a vendor software patch to remediate a newly discovered vulnerability.
  * Rebuilding a compromised server from a clean, hardened golden image.

### 3.5 Compensating Controls (Alternative Controls)
* **Objective:** Provide a temporary or permanent **substitute safeguard** when a primary standard control cannot be implemented due to technical, architectural, or budgetary limitations.
* **Timing:** Applied when standard controls are unfeasible.
* **Examples:**
  * A legacy industrial control system (ICS) running Windows XP cannot support modern endpoint antivirus; the compensating control is placing it on an isolated, strictly filtered VLAN with no internet access.
  * A web application cannot implement MFA due to architectural constraints; the compensating control is restricting access strictly via IP-whitelisted VPN tunnels.

### 3.6 Directive Controls
* **Objective:** **Dictate, mandate, or guide** specific acceptable behavior and policy compliance within an organization.
* **Timing:** Prior to actions (establishing expectations).
* **Examples:**
  * An Acceptable Use Policy (AUP) prohibiting the use of personal cloud drives on company machines.
  * Clean desk / clear screen policy directives.
  * Mandatory annual cybersecurity compliance training modules.
  * Regulatory guidelines requiring data encryption for credit card data (e.g., PCI-DSS).

## 4. Synthesis: Categories vs. Functional Types Matrix

CompTIA scenario questions often pair a category with a functional type. Every security measure possesses both attributes simultaneously:

| Security Measure | Implementation Category | Functional Type | Reason / Logic |
| :--- | :--- | :--- | :--- |
| **Firewall Rule** | Technical | Preventive | Software/hardware logic directly blocking unauthorized packets. |
| **CCTV Camera** | Physical | Detective / Deterrent | Physical hardware that visibly deters intruders and records events. |
| **Acceptable Use Policy** | Managerial | Directive | Organizational document mandating user operational rules. |
| **System Backup Restoration** | Operational / Technical | Corrective | Restoring data post-incident to recover normal state. |
| **Warning Sign on Fence** | Physical | Deterrent | Material object psychologically discouraging perimeter trespass. |
| **VLAN for Legacy Device** | Technical | Compensating | Alternative network design replacing missing host-level controls. |
| **Motion Detector** | Physical | Detective | Physical hardware sensor alerting on unauthorized movement. |
| **Security Awareness Class** | Operational | Preventive / Directive | Human procedural instruction guiding behavior to prevent phishing. |

* **FIM:** File Integrity Monitoring
* **HIDS:** Host-based Intrusion Detection System
* **HVAC:** Heating, Ventilation, and Air Conditioning
* **ICS:** Industrial Control System
* **IDS:** Intrusion Detection System
* **IPS:** Intrusion Prevention System
* **MFA:** Multi-Factor Authentication
* **NGFW:** Next-Generation Firewall
* **NIDS:** Network-based Intrusion Detection System
* **SIEM:** Security Information and Event Management
* **UPS:** Uninterruptible Power Supply
* **VLAN:** Virtual Local Area Network
* **WAF:** Web Application Firewall
