## 1. Ciphers & Algorithms: Symmetric vs. Asymmetric

### 1.1 Core Comparison

| Attribute | Symmetric Encryption | Asymmetric Encryption (Public Key) |
| :--- | :--- | :--- |
| **Key Count** | Single shared secret key (used for both encrypt & decrypt) | Mathematically linked key pair: Public Key & Private Key |
| **Performance** | Extremely fast, low CPU/hardware overhead | Computationally expensive and slower |
| **Primary Use Cases** | Bulk data encryption (data at rest, full-disk encryption, active data stream payload) | Key exchange, digital signatures, identity verification |
| **Key Distribution Problem** | High risk; secret key must be pre-shared over an out-of-band channel | Resolved; public key is freely distributed; private key stays secret |

---

### 1.2 Symmetric Algorithms

* **AES (Advanced Encryption Standard):**
  * **Status:** Gold standard symmetric block cipher worldwide (FIPS 197).
  * **Block Size:** Fixed at 128 bits.
  * **Key Sizes:** 128, 192, or 256 bits (AES-256 is standard for top-secret/government classifications).
* **3DES (Triple Data Encryption Standard):**
  * **Mechanism:** Applies original 56-bit DES three times ($E(K_1) \rightarrow D(K_2) \rightarrow E(K_3)$) with effective 112-bit or 168-bit key strength.
  * **Status:** Deprecated and legacy. Replaced entirely by AES due to slow performance and vulnerabilities (e.g., Sweet32 64-bit block collision attacks).
* **Common Cipher Modes:**
  * **CBC (Cipher Block Chaining):** Requires an Initialization Vector (IV); encrypts previous ciphertext block with current plaintext block. Vulnerable to padding oracle attacks if improperly implemented.
  * **GCM (Galois/Counter Mode):** High-speed stream-like mode providing Authenticated Encryption with Associated Data (AEAD) for confidentiality and integrity simultaneously.

---

### 1.3 Asymmetric Algorithms

* **RSA (Rivest-Shamir-Adleman):**
  * **Mathematical Foundation:** Factoring the product of two large prime numbers.
  * **Key Sizes:** Minimum standard $\ge 2048$ bits; 3072 or 4096 bits recommended.
  * **Functions:** Used for both encryption and digital signatures.
* **ECC (Elliptic Curve Cryptography):**
  * **Mathematical Foundation:** Algebraic structures of elliptic curves over finite fields.
  * **Key Advantage:** Equivalent security to RSA with significantly smaller key sizes (e.g., 256-bit ECC $\approx$ 3072-bit RSA).
  * **Ideal For:** Resource-constrained devices (mobile, IoT, embedded systems, smart cards) due to lower CPU, battery, and bandwidth consumption.
  * **Variants:** ECDSA (signatures), ECDH (key exchange).
* **Diffie-Hellman (DH):**
  * **Function:** Key exchange protocol enabling two parties to negotiate a shared symmetric key over an insecure public channel without transmitting the secret itself.
  * **Note:** Does not perform direct bulk data encryption or digital signatures by itself.
  * **DHE (Ephemeral DH) & ECDHE:** Uses temporary, single-session keys to deliver Perfect Forward Secrecy (PFS).

## 2. Integrity & Authenticity

### 2.1 Cryptographic Hash Functions

* **Characteristics:**
  * One-way mathematical function (pre-image resistance).
  * Fixed output length regardless of input size.
  * Avalanche effect: A 1-bit input change drastically alters the resulting hash.
* **SHA-256 (Secure Hash Algorithm 2):**
  * Generates a 256-bit digest; part of the SHA-2 family (SHA-224, 256, 384, 512).
  * Current industry standard across certificates, blockchain, and OS integrity checks.
* **SHA-3:**
  * Uses the Keccak permutation-based sponge construction (fundamentally different architecture from the Merkle-Damgård structure used in SHA-1 and SHA-2).
  * Serves as a backup standard should mathematical vulnerabilities ever emerge in SHA-2.
* **Collision Resistance:**
  * The mathematical guarantee that it is computationally infeasible to find any two distinct inputs $x$ and $y$ such that $H(x) = H(y)$.
  * Legacy hashes like MD5 and SHA-1 are deprecated due to demonstrated collision vulnerabilities.

---

### 2.2 HMAC & Digital Signatures

* **HMAC (Hash-based Message Authentication Code):**
  * **Structure:** Combines a cryptographic hash function (e.g., SHA-256) with a pre-shared secret key ($\text{HMAC-SHA256}$).
  * **Properties Provided:** **Integrity** and **Authenticity** (only a party with the shared secret could generate the valid hash).
  * **Limitation:** Does **not** provide non-repudiation (both parties hold the shared key).
* **Digital Signatures:**
  * **Process:**
    1. Sender hashes the message: $H = \text{Hash}(M)$.
    2. Sender encrypts the hash with their **Private Key**: $\text{Sig} = E_{\text{priv}}(H)$.
    3. Recipient decrypts signature using sender's **Public Key**: $H' = D_{\text{pub}}(\text{Sig})$.
    4. Recipient hashes the received message and verifies $H == H'$.
  * **Properties Provided:** **Integrity**, **Authentication**, and **Non-Repudiation** (the sender cannot deny transmitting the message because only their private key could sign it).

## 3. Public Key Infrastructure (PKI)

### 3.1 Trust Hierarchy & Operations

* **Certificate Authority (CA):** Trusted third-party entity that issues, signs, and manages digital X.509 certificates binding a public key to an entity's verified identity.
* **Registration Authority (RA):** Subordinate entity that verifies the identity of the requester before requesting the CA to sign the certificate.
* **Certificate Signing Request (CSR):**
  * Generated on the applicant's server.
  * Contains the applicant's **public key** and identity details (Common Name / FQDN, Organization, Country, Subject Alternative Names [SAN]).
  * Signed by the applicant's private key before being sent to the CA for signing.

---

### 3.2 Certificate Revocation: CRL vs. OCSP

* **CRL (Certificate Revocation List):**
  * A published, periodically updated, digitally signed list of revoked serial numbers maintained by the CA.
  * **Drawbacks:** File size scales with revocations; high bandwidth consumption; latency window between list updates (clients might accept a recently revoked certificate).
* **OCSP (Online Certificate Status Protocol):**
  * Real-time query protocol over HTTP. Client queries the CA responder with a certificate serial number; responder answers `Good`, `Revoked`, or `Unknown`.
  * **Drawback:** Privacy concerns (CA sees which sites user visits) and performance overhead during high-volume spikes.
* **OCSP Stapling:**
  * The web server periodically queries the OCSP responder directly, caches the timestamped, CA-signed OCSP response, and "staples" it to the initial TLS handshake sent to clients.
  * Solves CA server bottlenecks and protects client browsing privacy.

---

### 3.3 Certificate Encoding & File Formats

| Format | Extension(s) | Encoding | Characteristics / Use Cases |
| :--- | :--- | :--- | :--- |
| **PEM** (Privacy Enhanced Mail) | `.pem`, `.crt`, `.cer`, `.key` | ASCII (Base64) | Common on Linux/Apache/Nginx. Starts with `-----BEGIN CERTIFICATE-----`. |
| **DER** (Distinguished Encoding Rules) | `.der`, `.cer` | Binary | Common in Java platforms and Windows environments. Cannot be opened in a standard text editor. |
| **PKCS#12 / PFX** | `.pfx`, `.p12` | Binary | Container format storing the **server certificate, intermediate CA chain, and private key** together in a single password-protected file. |
| **PKCS#7 / P7B** | `.p7b`, `.p7c` | ASCII (Base64) | Contains public certificates and CA chains; **never includes private keys**. |

## 4. Key Concepts & Advanced Applications

### 4.1 Data Obfuscation & Protection Techniques

* **Steganography:**
  * Concealing data inside another non-suspicious carrier medium (e.g., hiding encrypted text inside the least significant bits [LSB] of an image, audio, or video file).
  * Obscures the *existence* of the message, whereas encryption obscures the *meaning*.
* **Tokenization:**
  * Replaces sensitive data (e.g., credit card Primary Account Numbers [PAN]) with a randomly generated, non-sensitive surrogate value ("token").
  * The actual mapping is isolated in a secure, centralized Token Vault.
  * If a tokenized database is breached, the tokens have zero mathematical relationship to the original data and cannot be reverse-engineered without the vault.
* **Data Masking (Obfuscation):**
  * Hiding or scrambling portions of sensitive data for display or non-production environments (e.g., showing only `****-****-****-1234` on receipts, dynamic database masking for test environments).

---

### 4.2 Perfect Forward Secrecy (PFS)

* **Definition:** A property of secure key-exchange protocols ensuring that compromise of a server's long-term private key does **not** compromise past session keys.
* **Mechanism:** Rather than encrypting a symmetric session key with the server's long-term RSA key, the server and client dynamically compute independent, temporary (ephemeral) session keys via **DHE** or **ECDHE**.
* **Impact:** An attacker who records encrypted network traffic for years cannot decrypt historical traffic even if they later gain physical access to the server's private key.

---

### 4.3 Blockchain Fundamentals

* **Structure:** A decentralized, distributed, append-only cryptographic ledger consisting of ordered records ("blocks").
* **Chaining Mechanism:** Each block contains a cryptographic hash of the previous block's header, creating an immutable cryptographic chain.
* **Tamper Evidence:** Modifying a transaction in an earlier block invalidates all downstream block hashes across the distributed network.
* **Consensus Mechanisms:** Algorithms (Proof of Work [PoW], Proof of Stake [PoS]) ensuring all decentralized nodes agree on the legitimate ledger state without relying on a central authority.
* **Security Uses:** Immutable audit logging, verifiable decentralized identity, supply chain tracking, and smart contract execution.
