# CompTIA Security+ (SY0-701) Study Notes

## Domain 1.0: General Security Concepts (12%)

### Objective 1.2: Fundamental Security Concepts

## 1. The CIA Triad

The core model guiding all information security policies and control implementations.

### 1.1 Confidentiality
* **Definition:** Ensuring sensitive data is shielded from unauthorized observation, disclosure, or interception.
* **Core Mechanisms:**
  * **Encryption:** Symmetric (AES) and asymmetric (RSA/ECC) algorithms for data at rest, in transit, and in use.
  * **Access Controls:** Least privilege permissions, Access Control Lists (ACLs), role-based permissions.
  * **Data Masking & Obfuscation:** Concealing sensitive fields on screens and databases.

### 1.2 Integrity
* **Definition:** Ensuring information, software, and systems remain accurate, consistent, and unaltered by unauthorized parties or processes.
* **Core Mechanisms:**
  * **Hashing:** Cryptographic hashes (SHA-256) verifying payload or file consistency.
  * **Digital Signatures:** Cryptographically proving author identity and preventing payload tampering.
  * **File Integrity Monitoring (FIM):** Alerting when critical system binaries, configurations, or registries change.

### 1.3 Availability
* **Definition:** Ensuring authorized users possess timely, reliable access to critical assets, data, and services whenever needed.
* **Core Mechanisms:**
  * **Redundancy & High Availability (HA):** Fault-tolerant clusters, load balancers, RAID arrays, redundant power (UPS/generators).
  * **Disaster Recovery & Backups:** Geographic replication, verified backup snapshots, incident response automation.
  * **DDoS Mitigation:** Scrubbing centers, rate limiting, and content delivery networks (CDNs).

## 2. Core Security Tenets & AAA Framework

### 2.1 Non-Repudiation
* **Definition:** A cryptographic guarantee ensuring an individual or entity cannot deny having performed a specific transaction, message transmission, or operational action.
* **Primary Implementation:** **Digital Signatures** combining asymmetric cryptography and hashing. Because only the sender possesses their private signing key, the signature uniquely proves origin and acceptance.

### 2.2 The AAA Framework
* **Authentication:**
  * **Concept:** Verifying that an entity is genuinely who they claim to be.
  * **Factors:** Something you know (password/PIN), something you have (hardware token/authenticator app), something you are (biometrics), somewhere you are (geolocation), something you do (keystroke dynamics).
* **Authorization:**
  * **Concept:** Determining what resources and actions an authenticated subject is permitted to access.
  * **Models:** Discretionary Access Control (DAC), Mandatory Access Control (MAC), Role-Based Access Control (RBAC), Attribute-Based Access Control (ABAC).
* **Accounting (Auditing):**
  * **Concept:** Tracking, logging, and auditing user activity, session times, accessed files, and resource consumption.
  * **Use Cases:** Forensics investigations, non-repudiation audit trails, billing, regulatory compliance validation.

## 3. Zero Trust Architecture (ZTA)

Zero Trust operates on the guiding principle: **"Never trust, always verify."** Trust is never granted implicitly based solely on network location or physical perimeter placement.

### 3.1 Elimination of Implicit Trust Zones
* **Traditional "Castle-and-Moat" Model:** Once an attacker or insider traverses the outer firewall, the internal corporate network was treated as an implicit trust zone with wide lateral access.
* **Zero Trust Model:** Treats all network segments, endpoints, and requests as potentially hostile—whether originating inside the office LAN or out on the public internet. Every single transaction must be authenticated, authorized, and encrypted.

### 3.2 Planes of Architecture
* **Control Plane:**
  * The administrative decision-making infrastructure.
  * Responsible for evaluating policies, context, device health, risk metrics, and issuing access decisions/tokens.
* **Data Plane:**
  * The underlying communication path carrying actual user payloads and application traffic.
  * Enforces the verdicts dictated by the control plane (forwarding, inspecting, or dropping packets).

### 3.3 Core Zero Trust Components (NIST SP 800-207)
* **Policy Engine (PE):** Evaluates enterprise policy against current risk signals (user identity, device posture, location) to decide whether to grant or revoke access.
* **Policy Administrator (PA):** Translates the PE's decision into technical commands to establish or terminate communication paths. (PE + PA form the Policy Decision Point / PDP).
* **Policy Enforcement Point (PEP):** Gatekeeper mechanism residing directly on the data plane (e.g., API gateway, next-gen firewall, proxy) that intercepts connections and enforces access rules.

### 3.4 Microsegmentation
* **Definition:** Dividing workloads, data centers, and networks into granular, isolated zones down to individual workloads or containers.
* **Advantage:** Prevents **lateral movement**. If an adversary compromises a single web server, firewall microsegmentation prevents them from scanning or reaching neighboring database instances.

## 4. Deception & Disruption Technologies

Proactive defensive measures engineered to mislead, distract, delay, and detect adversaries actively operating inside an environment.

### 4.1 Honeypots
* **Definition:** A deliberately vulnerable decoy system or service placed on a network to attract attackers.
* **Purpose:** Divert attackers away from legitimate production systems, analyze adversary tactics, techniques, and procedures (TTPs), and trigger high-fidelity alerts.
* **High vs. Low Interaction:**
  * *Low-interaction:* Emulates basic network services (e.g., answering port 21/FTP with a fake banner); low risk and low maintenance.
  * *High-interaction:* Runs actual operating systems and applications; allows deeper behavioral observation but requires strict containment to avoid pivot attacks.

### 4.2 Honeynets
* **Definition:** An entire network segment of interconnected honeypots simulating a production subnet (decoy routers, servers, workstations).
* **Purpose:** Observes complex multi-stage attacks, internal lateral movement, and privilege escalation schemes in a contained sandbox.

### 4.3 Honeyfiles
* **Definition:** Decoy files placed intentionally on legitimate file shares or storage buckets with enticing names (e.g., `passwords_2026.xlsx`, `customer_credit_cards.csv`).
* **Purpose:** Legitimate employees have no operational need to open them; any read, write, or download access immediately trips an intrusion detection alarm.

### 4.4 Honeytokens
* **Definition:** Digital lures embedded into records, credentials, or code (e.g., fake API keys, canary database records, bogus AWS access keys).
* **Purpose:** If a honeytoken appears in use (e.g., an AWS key making an API call, or a fake email address receiving a message), it provides undeniable evidence of data exfiltration or credential theft.
