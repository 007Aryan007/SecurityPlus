# CompTIA Security+ Notes: 4.2 Asset & Vulnerability Management

This section covers how organizations identify, track, and manage their hardware and software assets, as well as the processes used to discover and patch security weaknesses before attackers can exploit them.

## 1. Asset Management

You cannot secure what you do not know you have. Proper asset management is foundational to a strong security posture.

### Asset Discovery and Tagging

* **Asset Discovery:** The process of identifying all devices and software running on the network.
  * **Active Discovery:** Tools actively ping or scan the network to find responding devices (can be noisy and alert IDS/IPS).
  * **Passive Discovery:** Monitoring network traffic to identify devices as they communicate (stealthier, but might miss offline devices).
* **Tagging:** Applying physical (barcodes, RFID tags) or logical (metadata, organizational unit labels) markers to assets. This helps track location, ownership, and data classification levels for compliance and inventory control.

### Asset Lifecycles

Every hardware, software, and data asset goes through a lifecycle. Security must be integrated at every phase.

1. **Procurement/Acquisition:** Purchasing assets from trusted vendors to avoid supply chain attacks (e.g., counterfeit hardware or pre-installed malware).
2. **Deployment:** Hardening the system, applying secure baselines, and integrating it into the environment.
3. **Operations & Maintenance:** Regular patching, monitoring, and updating throughout the asset's useful life.
4. **Decommission/Disposal:** Securely wiping data (sanitization per NIST 800-88), recycling hardware, and revoking software licenses. Failing to secure the disposal phase can lead to major data breaches.

## 2. Vulnerability Management

Vulnerability management is the continuous, proactive process of identifying and fixing security flaws in the environment.

### Vulnerability Identification

Usually performed using automated vulnerability scanners (like Nessus, Qualys, or OpenVAS).
* **Non-credentialed Scan:** The scanner acts as an outside attacker with no login rights. It only sees what is exposed to the network (e.g., open ports, visible banners).
* **Credentialed Scan:** The scanner is given administrator/root login credentials. It can log into the machine and check registry keys, software versions, and internal configurations. This is much more accurate and comprehensive.

### Tracking and Scoring Vulnerabilities

* **CVE (Common Vulnerabilities and Exposures):** A standardized, public dictionary of known software and hardware vulnerabilities. Each vulnerability is given a unique identifier (e.g., CVE-2021-44228 for Log4Shell), allowing security professionals worldwide to speak the same language.
* **CVSS (Common Vulnerability Scoring System):** A standardized framework for rating the severity of a vulnerability based on its exploitability and impact. Scores range from **0.0 to 10.0**:
  * **0.0 - 3.9:** Low
  * **4.0 - 6.9:** Medium
  * **7.0 - 8.9:** High
  * **9.0 - 10.0:** Critical

### Validation (False Positives & Negatives)

Scanners are not perfect. Security analysts must validate the results.

* **False Positive:** The scanner reports a vulnerability exists, but it actually does not. (Result: Wastes the security team's time and resources).
* **False Negative:** The scanner reports the system is secure, but a vulnerability *does* exist. (Result: Highly dangerous, gives a false sense of security while leaving a hole open for attackers).

### Patch Remediation Workflows

Patch management is the process of applying updates to software to fix vulnerabilities. The standard workflow is:

1. **Identify/Assess:** A vulnerability is discovered, and a patch is released by the vendor.
2. **Test:** **CRITICAL STEP.** Patches must be tested in an isolated sandbox or development environment first. Applying patches directly to production can break custom applications or cause system crashes.
3. **Deploy:** Roll out the patch to production systems, often in phased waves to minimize risk.
4. **Verify:** Rescan the network to confirm the vulnerability has been successfully remediated.
