# CompTIA Security+ Notes: 4.6 Incident Response & Digital Forensics

This section focuses on how organizations handle security breaches (Incident Response) and how they legally and technically gather evidence after an attack (Digital Forensics).

## 1. Incident Response Lifecycle

The CompTIA Security+ exam typically uses the NIST (National Institute of Standards and Technology) standard for the Incident Response (IR) lifecycle. You must know these steps in order.

1. **Preparation:** The most important phase. Occurs *before* an incident happens. Includes writing policies, training users and the IR team, acquiring tools, and ensuring backups are running.
2. **Detection & Analysis:** Identifying that an incident has occurred (via SIEM alerts, IDS, or user reports) and analyzing the scope, impact, and root cause.
3. **Containment:** Stopping the spread of the attack. 
   * *Short-term:* Disconnecting a compromised host from the network.
   * *Long-term:* Patching neighboring systems or routing traffic to a backup site. 
   * **Key Rule:** Do not power off the machine if you need to perform forensics later (you will lose RAM).
4. **Eradication:** Removing the threat from the environment. This means deleting malware, disabling compromised accounts, and applying necessary patches.
5. **Recovery:** Restoring systems back to normal business operations. This includes restoring from backups, rebuilding servers, and closely monitoring the network for returning threats.
6. **Lessons Learned:** Often called the "Post-Incident Review." The team meets to discuss what went well, what failed, and how to improve the Preparation phase for next time.

## 2. Forensic Investigation

Digital forensics is the process of collecting and analyzing data in a way that is legally admissible in a court of law.

### Order of Volatility

When collecting evidence, you must collect the most volatile (easily lost) data first before it disappears or the system powers down. The standard order is:
1. **CPU Registers / Cache:** Changes in nanoseconds.
2. **RAM (Random Access Memory):** Contains active network connections, running processes, and sometimes unencrypted passwords. Lost instantly if the machine is powered off.
3. **Swap / Page File:** Temporary memory written to the hard drive.
4. **Hard Drives (Local Data at Rest):** Persistent storage.
5. **Remote Logs / Cloud Data:** Stored elsewhere, less likely to be immediately altered by the local system shutting down.

### Key Forensic Concepts

* **Chain of Custody:** A chronological paper trail that documents exactly who collected the evidence, who handled it, where it was stored, and when. If the chain is broken, the evidence can be thrown out of court.
* **Legal Hold:** A legal directive to preserve all relevant data, overriding normal data retention/deletion policies (e.g., preventing a 30-day email auto-delete process).
* **Forensic Disk Imaging:** You should **never** analyze the original hard drive. Instead, create a bit-by-bit copy (a clone) using tools like `dd`. You must generate a cryptographic hash (e.g., SHA-256) of the original drive and the image to prove they are identical and that data integrity was maintained.
* **Memory Capture:** The process of dumping the contents of RAM to a file before pulling the plug on a machine, crucial for finding fileless malware or encryption keys.

## 3. Data Sources

During the "Detection & Analysis" phase, incident responders rely heavily on various logs.

* **Syslog:** The standard logging protocol and format used by Linux/Unix systems, routers, switches, and firewalls. Often centralized in a SIEM.
* **Windows Event Logs:** Microsoft's logging system. The three main logs are System (OS events), Application (software events), and Security (logins, privileges). Viewed using Event Viewer.
* **Firewall / Proxy Logs:** Essential for tracking network traffic. Firewalls show allowed/blocked IP connections, while Proxies are excellent for tracking URLs visited and identifying data exfiltration or Command and Control (C2) traffic.
* **DNS Queries:** Monitoring DNS logs helps identify compromised hosts attempting to resolve known malicious domains (often used by ransomware to find its C2 server).
* **Authentication Records:** Logs showing login attempts (successes and failures). Crucial for spotting brute-force attacks, credential stuffing, and lateral movement by an attacker using stolen credentials.
