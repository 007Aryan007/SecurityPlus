# CompTIA Security+ Notes: 4.4 Identity and Access Management (IAM)

This section focuses on how organizations verify who a user is (Authentication), what they are allowed to do (Authorization), and how administrative accounts are secured.

## 1. Authentication & MFA

Authentication is the process of proving an identity. Relying on just a password (single-factor) is no longer sufficient; Multi-Factor Authentication (MFA) is the industry standard.

### Authentication Factors

To be true MFA, you must use at least two **different** categories of factors. (Using two passwords is just two single factors).

* **Knowledge (Something you know):** Passwords, PINs, security questions. *Vulnerable to phishing and brute-force attacks.*
* **Possession (Something you have):** Smart cards, hardware tokens (RSA SecurID), USB security keys (YubiKey), SMS codes, authenticator apps on a smartphone.
* **Inherence (Something you are):** Biometrics such as fingerprints, facial recognition, retina scans, and voice prints.

*(Note: The exam may also mention "Somewhere you are" for geolocation and "Something you do" for behavioral biometrics like typing speed).*

### Passwordless Authentication

Moving away from passwords entirely to eliminate phishing and credential stuffing attacks.

* **FIDO2 (Fast Identity Online):** A set of standards that enables users to leverage common devices (mobile phones, biometric readers, hardware keys) to easily authenticate to online services without a password.
* **WebAuthn (Web Authentication):** The web API component of FIDO2. It allows websites to communicate securely with a user's authenticator device (like a YubiKey or Windows Hello) to log in directly via the browser, ensuring strong, cryptographic, phishing-resistant authentication.

## 2. Federation & Directory Services

Directory services store user identities, while federation allows users to use those identities across different, completely separate organizations.

### Federation and Web SSO

* **SAML (Security Assertion Markup Language):** An XML-based standard used heavily for enterprise Web Single Sign-On (SSO). It allows a user to authenticate at their company's identity provider and pass an "assertion" (a trusted ticket) to a third-party service (like Salesforce) to log in automatically.
* **OAuth 2.0:** Primarily an **Authorization** protocol (delegated access). It allows an application to access a user's data on another application *without* giving away the password. (e.g., Clicking "Allow this app to access your Google Contacts").
* **OpenID Connect (OIDC):** An **Authentication** layer built on top of the OAuth 2.0 framework. While OAuth handles the access, OIDC handles verifying *who* the user is, usually generating a JSON Web Token (JWT).

### Traditional Directory Services

* **Kerberos:** The primary authentication protocol used in Microsoft Active Directory. 
  * Uses a system of **Tickets** (Ticket-Granting Ticket / TGT) to prove identity.
  * Provides **mutual authentication** (the user authenticates to the server, and the server authenticates to the user).
  * Heavily reliant on **time synchronization** (NTP) to prevent replay attacks.
* **LDAP (Lightweight Directory Access Protocol):** Used to read, write, and search directory services (like Active Directory) using a hierarchical X.500 format (e.g., `CN=John,OU=Sales,DC=Company,DC=com`). 
  * **LDAPS (LDAP Secure):** Standard LDAP (Port 389) sends data in plaintext. LDAPS (Port 636) encrypts the LDAP traffic using TLS.

## 3. Access Models & PAM

Access models determine how permissions are assigned once a user is authenticated. 

### Access Control Models

* **RBAC (Role-Based Access Control):** Permissions are tied strictly to a user's job role or group (e.g., the "Accountant" group). Users are placed into groups, and groups are granted access. This is the most common model in modern enterprises due to ease of administration.
* **ABAC (Attribute-Based Access Control):** The most granular and flexible model (often called "Next-Gen" access control). It evaluates multiple attributes or dynamic conditions before granting access. 
  * *Example:* "Allow access only if User=Manager (Subject Attribute) AND Device=Corporate Laptop (Device Attribute) AND Time=8am-5pm (Environmental Attribute)."

### Privileged Access Management (PAM)

PAM focuses specifically on securing highly privileged accounts (administrators, root accounts) because compromising these accounts gives an attacker full control.

* **Vaulting:** Instead of administrators knowing the root password, the password is mathematically complex and stored in a secure PAM vault. When an admin needs access, they check out the password from the vault. Once they are done, the vault automatically randomizes and changes the password.
* **Just-in-Time (JIT) Access:** The concept of "Zero Standing Privileges." An administrator's account normally has standard user rights. When they need to perform an admin task, they request elevation. They are granted admin rights *only* for the specific time needed to complete the task (e.g., 2 hours), after which the privileges are automatically revoked.
